Retrieval-Augmented Generation: Bridging Knowledge and Generation

Retrieval-Augmented Generation (RAG) is a hybrid AI architecture that combines a retrieval system with a
generative language model to produce more accurate, up-to-date, and grounded responses.

Introduced by Lewis et al. from Facebook AI Research (FAIR) in 2020, RAG addresses the knowledge cutoff
problem inherent in parametric language models. Instead of relying solely on memorized training data,
a RAG system retrieves relevant documents from an external knowledge base at inference time and conditions
the generator on those documents.

The standard RAG pipeline consists of three stages:
1. Indexing: Documents are chunked, embedded using a dense encoder (e.g., OpenAI Embeddings, Sentence-BERT,
   or BGE models from BAAI), and stored in a vector database such as Pinecone, Weaviate, Chroma, or FAISS.
2. Retrieval: Given a user query, the system encodes the query and performs approximate nearest-neighbor (ANN)
   search to retrieve top-k relevant chunks.
3. Generation: The retrieved chunks are prepended to the prompt, and an LLM (e.g., GPT-4, Claude, Mistral)
   generates the final answer grounded in the retrieved context.

Naive RAG suffers from several limitations: irrelevant retrievals, context window overflow, and faithfulness
issues where the model ignores retrieved content. Advanced RAG techniques address these with query rewriting,
hybrid search (BM25 + dense), reranking using cross-encoders (e.g., Cohere Rerank, MS MARCO), and
iterative retrieval strategies.

Graph-based extensions of RAG — known as GraphRAG — incorporate structured knowledge graphs to improve
multi-hop reasoning. Microsoft Research released a GraphRAG toolkit in 2024, enabling community-level
summarization over large document corpora using entity graphs.

RAG is now the dominant approach for enterprise AI applications, powering customer support systems,
document Q&A, legal research tools, and scientific literature assistants.
